# 牛马片场：新手读图说明

本项目把一段长视频制作成可审核、可准备发布的短片：导入原片，识别声音生成原文，用 AI 找候选片段，用 FFmpeg 切视频，交给用户审片；之后再准备文案、排期和投稿。

技术：Python + FastAPI 负责后台；HTML/CSS/JavaScript + Jinja2 负责页面；SQLite 记状态；FFmpeg/FFprobe 处理媒体；faster-whisper 或火山引擎转写；Codex CLI、远程兼容 API 或本地接口负责 AI；Playwright + Chrome 执行平台页面操作。依赖以 requirements.txt、requirements.in 为证。

源码基线：master，提交 `5ebe60d20419314a20e94f2eb88cf8a850ae7a11`，VERSION 为 2.6.0。源码链接固定到此提交。所有被引用源码都核对了当前工作区与该提交的逐行内容；Windows 换行差异不改变引用行号。

## 主流程：素材池批次自动制作到待审片

例子是假设用户选择一条自己拥有的视频，勾选自动生产。这里描述代码流程，本次没有执行这个例子。

1. 用户在素材池预览并登记原片，选择内容类型、Prompt、Provider 和字幕方式，然后明确确认批次。浏览器发送 JSON 到 `/api/material-batches`，携带固定请求编号，避免重试创建另一批。证据：app/routers/materials.py:18–32；app/static/js/material-batches.js:153–176。
2. 批次服务在一次 SQLite 事务中登记 material_batches、tasks、material_batch_items 和 material_import Job，冻结制作配置。此时登记工作，复制由 Job 执行。证据：app/services/material_batch_service.py:66–107。
3. WorkflowJobRunner 从 SQLite 领取待办，用独立 Python 子进程执行。导入服务只读原片，复制到托管 source 目录，校验字节并保存凭据；只有 auto_production=true 才登记后续 auto_pipeline。证据：app/services/job_worker.py:282–335；material_import_service.py:115–175；batch_pipeline_service.py:48–55。
4. PipelineEngine 依序调用制作服务：FFmpeg 抽出声音；转写服务生成带时间戳的 transcript.md；AI 读取原文和冻结配置，保存候选、评分与分析历史；FFmpeg 按候选起止点生成新切片批次。数据库保存状态和版本，文件目录保存实际产物。证据：pipeline_engine.py:143–154；transcript_service.py:267–280；ai_analysis_workflow_service.py:1513–1567、1615–1632；video_cut_workflow_service.py:620–651。
5. 自动批次完成预切后必须返回 pending_review，统一待办等待用户看实际视频。分析不完整或质量门槛未通过会阻止切片；“任务完成预切”也不会等于“可以投稿”。证据：pipeline_engine.py:209–215；batch_pipeline_service.py:58–72；video_cut_workflow_service.py:561–589。
6. 用户确认当前成片，后台核对成片摘要并保存 production_reviews。保留原画面可继续准备；新增字幕先审核和渲染验证。用户再进入发送中心准备内容。明确排期或立即发送后，Scheduler/Executor 才交给独立 Chrome Worker；不确定投稿结果返回人工复核。证据：production_review_service.py:246–282、145–174；publish_service.py:2177–2208；publish_scheduler.py:386–441。

主要流程的最终自动结果是“本地预切文件 + 数据库版本凭据 + 待人工审片”，实际发布属于后续独立操作。

# 动态排期使用与验收

本功能仅面向抖音账号“康熙来了”，使用本地统计，不调用模型。代码已完成，生产部署和启用需要另行授权。

## 如何使用

1. 在发送中心为作品选择目标账号，打开设置排期，选择“数据动态排期”。默认每天最多 8 条，可以修改；默认窗口为北京时间 07:00–23:59，间隔至少 90 分钟。
2. 点击预览，检查每条具体时间、样本数及“优先 / 测试”原因，再确认应用。已有当天排期保持不变；预览后如果任务或策略发生变化，重新预览。
3. 账号自动调整启用时纳入符合条件的现有排期。之后官方作品数据成功导入会登记持久请求，后台仅调整明天起尚未领取的受管任务，保留视频顺序。
4. 在排期列表选择任务后可固定时间退出管理，也可重新加入。单条手动改期和固定间隔批量改期默认固定。关闭账号自动调整只停止后续调整，具体时间继续保留。

## 统计口径

- 数据只取目标账号已确认导入的官方作品表，每个作品键保留最新快照；账号趋势表不参与。优先最近 30 天发布、采集时至少满 72 小时的作品；可比较作品不足 30 条时扩展至 90 天，仍不足则不生成评分。
- 发布至采集年龄分为 3–7 天、7–14 天、14–30 天、30 天以上；片长分为未知、60 秒以内、60–120 秒、120 秒以上。同年龄同片长至少 8 条，否则退到同年龄；仍不足则排除。
- 每条播放除以比较组播放中位数，分母至少 1；比值截断在 0.25–4，降低离群值影响。按北京时间每两小时求比值中位数，再以 `1 + (中位比值 - 1) × n / (n + 5)` 收缩；不足 5 条统一记 1，并标记待验证。
- 分数至少 1.2 标记较强，最多 0.8 标记偏弱，其余一般。完播率与涨粉中位数只用于解释，不影响排序。这是观察到的相关性，不能证明发布时间导致播放差异。
- 最新采集超过 7 天或数据不足时，已有排期保留；新排期使用 09、11、13、15、17、19、21、23 点测试基线，受窗口和已有占位限制。

## 分配与并发边界

半小时候选先检查容量与最小间隔，再按较强分数和轮换探索贪心选择可行组合。每日测试名额为每日数量四分之一向上取整；每天 8 条对应 6 个优先、2 个测试。分数相同优先原时间；测试位结合已有曝光、时段样本数和日期轮换。固定任务、已发布、执行中及待复核任务占位，不足顺延，不缩短间隔。

策略、任务快照、日期与具体预览时间组成 SHA-256 凭证。应用时在 `BEGIN IMMEDIATE` 中重算并核对凭证，检查任务状态与更新时间，再原子写入全批。后台重排请求与官方导入同事务登记、按来源幂等；数据库写失败回滚整批并保留待处理请求供后续周期恢复，不产生部分改期。无法计算的无效请求有失败记录，不阻塞后续账号或正常发布。

迁移 `20260906_01_adaptive_schedule` 增加策略、请求、审计表及任务动态/固定标记，迁移前使用现有在线备份机制。迁移本身不启用账号、不改现有时间。

## 接口

- 现有批量预览、应用和续接请求增加 `schedule_mode=adaptive`、`account_id`、`daily_limit`、`min_gap_minutes`；缺省仍为固定间隔。
- 动态应用提交预览返回的 `strategy_token` 和具体 `job_id / scheduled_at_utc` 对，不能自行替换时间。
- `GET /api/publish/schedules/adaptive` 查看账号策略、数据与调整记录。
- `PATCH /api/publish/schedules/adaptive/{account_id}` 保存策略与启停。
- `PATCH /api/publish/jobs/{job_id}/adaptive` 固定退出或重新加入。

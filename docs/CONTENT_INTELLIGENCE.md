# Content Intelligence：人工经验与受控实验

## v2.5.5 PR3c：官方实验与人工策略变更

`challenger_experiment_service` 复用 content_improvement_experiments/items、官方指标、冻结报告和 ai_prompt_versions，不增加另一套作品事实库。正式实验必须显式选择报告及对照组，固定 `five_second_completion_rate` 为提高方向的主指标，护栏为完播率、两秒跳出率和观看比例。没有官方基线仍可人工审片、保存草稿、创建逐步试验任务，不能产生正式作品实验。

报告 schema v2 增加逐作品导出周和执行条件；原 v1 报告只读保留，缺失条件不回填。对照组精确匹配 Champion Prompt 版本、Profile 版本/哈希/规则，初始与成片边界一致；按采集年龄及实际 Provider/模型、七项候选设置、完整视觉策略/运行状态、综艺反馈快照哈希分组。Run 的声明还必须匹配其真实冻结 Job。未知设置不是关闭视觉或空反馈。每组至少 20 个独立归因作品、3 个完整 SHA 原片身份和3 个属于这些作品的官方导出周，主指标不能缺失，截断查询不允许达标。展示缺失与护栏，不做因果声明；转写版本、音频算法和代码版本尚未成为可比较的 Run 证据，不能宣称严格随机单变量实验或效果已证实。

`POST /challengers/{id}/experiments` 在写事务内冻结选定报告、整组作品/快照引用、版本和控制条件；同 Challenger 只建一个实验，重试同基线返回已有实验，不能重新挑选更有利的证据。两条现有归属 API 都在写事务中验证 publish_job → output_clip → clip_candidate → ai_analysis_run → workflow_job，要求显式试验绑定及完整策略相符，投稿执行后仍不可改归属。历史已发布输出随后 inactive 不抹掉原作品；当前入组仍要求有效成片。最新 unmatched 不复活旧匹配，同批多个导出键对应一 Job 为歧义，时长不用当前可编辑候选倒推。

入组还前置验证 Run 完整性、唯一初始候选以及实际切片起止/时长，不能把人工改边界的成片当成同一个原始 AI 选择。旧非 Challenger 实验继续原先的统计及归属路径（含历史时长 fallback）；新严格口径只对绑定实验生效，不追改旧结论。

完成实验时保存带 hash 的人工结论及当时完整统计；后续官方同步不会改写该结论。`keep` 不启用策略。`GET /experiments/{id}/policy-preview` 显示当前/目标正文，`POST .../policy-events` 另需明确确认、预览 hash 和请求 UUID，在事务内比较当前 Profile 与正式 Prompt，拒绝覆盖其他人工改动。正式启用只改变既有正式预设的后续任务正文，追加/复用原 Prompt 版本；Profile/评分不变。回退恢复启用前原始正文并记录版本，已冻结任务均不变。同 UUID 迟到重试返回原记录，不会在回退后再次启用。回退后再次尝试须新草稿与实验，不能复用旧证据反复上线。

回退以停用新入口并保留增量表、证据与版本为优先；已经人工启用的策略可走独立确认回退。禁止删除迁移账本或用旧库覆盖升级后记录；完整恢复遵循停服务、保留当前快照及核对外部发布事实的既有流程。工程测试使用合成官方数据与隔离数据库，不代表真实节目策略有效。

## v2.5.5 PR3b：显式试验任务

草稿详情提供 `/tasks/new?challenger_id=...`，复用原上传页面和任务服务。页面只显示草稿的 Profile/Prompt，展示修改差异，必须勾选“使用未验证 Challenger”后才提交。上传字段 `challenger_id/challenger_sha256/confirm_challenger` 是明确的试验选择，不是普通任务默认项。预设保持 archived，不开放到普通选择器，也不会改变原正式 Prompt。

`challenger_trial_service.prepare_trial()` 在任务写事务内验证草稿/报告哈希、实际 Prompt 和当前受支持 Profile 版本，同时确认 Champion 正文仍与草稿基线一致。原任务创建、Prompt/Profile/Provider/视觉冻结继续执行，然后为 task_generation_rules 绑定 Challenger ID/证据哈希；同事务将草稿标为 trial。没有创建官方作品实验。未知/过期策略、未确认、错误 Prompt/Profile 和 auto_mode 直接拒绝；已存在试验任务仍保留自己的旧版本。

新 Job 的 generation_snapshot_v1.prompt 增加 Challenger 标记；读取同时核对任务绑定、草稿、Prompt 版本与 Profile 版本。缺失整个新快照或标记不能当作旧 Job 回退；旧任务没有绑定时保持原恢复解释。AI Run 在原 analysis_meta 保存同一标记和原有实际策略字段，提交事务再次比较 Job/实际策略，Run 插入、已提交结果恢复和历史重建均验证标记与版本。损坏 Run 拒绝恢复且不重发模型；历史页面显示试验来源链接。继续使用既有 AI checkpoint 和原子提交。

试验任务禁止改绑 Prompt/Profile，详情固定只读正文；手动分析不执行旧页面的自动保存 Prompt 操作。候选数量、目标、Provider/视觉仍由用户显式选择并随 Job 冻结，后续实验必须比较实际执行条件，不能仅靠试验标签。auto_pipeline Job 被拒绝；试验按原手动步骤处理，人工审片、内容准备和发布分别操作。此阶段不开放正式启用。

迁移 18 `20260915_04_challenger_trials` 增加两个可空字段、外键、索引和绑定不可覆盖约束。旧任务/Job/Run 不回填。回退时撤下新试验入口并保留增量结构和历史证据；已创建试验保持可读，不能把它错误改绑康熙正式 Prompt。

## v2.5.5 PR3a：人工 Challenger 草稿

冻结报告可打开 `/content-review/challengers?report_id=...`。用户明确选择当前 Profile 和基线 Prompt，载入正文后填写假设及改动，保存到独立的归档预设和既有 `ai_prompt_versions`。草稿不改变原 `ai_prompt_presets` 正文或默认标记，不修改 Profile 头指针，不创建 Workflow Job、作品实验或发布任务。

第一阶段是 Prompt-only：完整 Profile JSON、内容哈希、规则版本、评分维度/权重/hard gates 原样冻结。当前 `_assert_supported()` 只接受代码支持的 Profile 配置；这里不会绕过它，也不把未执行的新权重当作试验结果。基线标注 `explicitly_selected_current_strategy`，不能将缺失历史证据追认为“报告已经使用过当前策略”。

`GET /api/content-review/challengers/context` 只读返回实际正式方案及基线哈希；`POST /api/content-review/challengers` 验证来源报告、预览基线和请求 UUID。正式方案在预览后改变、草稿没有实际改动或来源损坏时拒绝保存。事务内新增归档预设、Prompt 版本和 Challenger，重复/并发提交返回同一记录；不覆盖已存在草稿。读取核对报告、Profile 配置、两个 Prompt 版本和完整证据哈希。

第 17 项迁移新增 `content_strategy_challengers`，证据字段有不可变触发器、版本引用和索引。服务无更新生产策略接口；普通创建任务仍拒绝归档预设，因此草稿不能仅靠知道 ID 就用于生产。后续「启用试用」「建立正式实验」「记录结论」「正式启用」均是独立人工动作，必须在实际接入 PR 验证后才开放。

没有官方数据也能保存**未验证假设**，不能生成伪造的官方基线实验。回退可撤下草稿入口、保留归档预设及版本证据；不能删除正式数据或迁移账本来伪装旧二进制兼容。服务/集成测试覆盖原正式表未变、幂等、过期基线、损坏证据；迁移测试覆盖旧报告保留、失败回滚、并发与备份恢复；Chrome 覆盖 1440/390 布局、实际保存/重开、HTML 文本安全及没有额外生产写入。

## v2.5.5 PR2：作品特征与冻结报告

`POST /api/content-review/intelligence/reports` 显式生成报告，参数是账号（可空）、1–180 天和请求 UUID。同一请求重试返回原记录，配置不同返回 409；没有自动刷新覆盖报告。GET 列表/详情只读取，详情核对正文、配置、账号和 schema 哈希。新报告和人工统计在同一 SQLite 事务快照中读取，生成不调用 AI、同步、发布，也不改任何 Prompt/Profile。

### 事实与衍生特征

- 人工部分按生成时间纳入 Run，冻结统计及 Run/观察哈希/最后评价引用。作品部分按作品发布时间纳入，仅接受截止时间前已经提交的抖音官方作品导出，账号相互隔离。
- 先按官方导出合成键选最新，再按准确发布任务去重。合成键是标题和发布时间的指纹，不冒充平台真实作品 ID。改标题的跨批次记录只计一条；同一批次多个导出键指向同一个任务时标为归因歧义。较新未匹配记录不能使旧匹配复活。
- 发布任务、账号、成片、候选和 AI Run 的归属必须一致。时长优先官方字段，其次切片提交快照；后来修改的候选时长不能覆盖成片时长。初始分数、topic、hook、Prompt/Profile/规则版本来自该 Run 与不可变版本，缺失保持未知，不用当前任务配置补猜。
- 报告保存原始证据编号、原始观察哈希、衍生特征和提取器版本 `content-intelligence-v1`。没有复制另一套官方指标或反馈事实表，不保存全文转写和视觉截图。后续更新数据不改变旧报告。

### 分组、可信门槛与限制

片长、Profile、topic、hook、质量分区间、Prompt 版本与北京时间发布小时分组。每组再次隔离 Profile 和「采集时距发布 0–7/8–30/30 天以上」；未知年龄、未知 Profile 不能形成可信比较。原始作品数、已核验原片数、版本缺失、导出周、时间范围及每个指标的样本数/缺失率都保留。

一般作品组至少 20 条、Prompt 组至少 30 条，组内作品覆盖三个官方导出周，全部具备可核对策略证据及至少三个原片字节身份，且初始候选与成片提交边界一致，才达到比较门槛。人工改边界后的成片仍展示原始 AI 分数和实际时长，但不让旧评分给改过的成片背书；边界未知同样保守处理。指标存在缺失时该指标另标不足，不用干净子集给整个组背书。正文不会自动补齐未知历史。原片字节身份的限制沿用下文 PR1；这会使部分历史文字任务只能获得描述统计，不能假装达到门槛。

只有相同 Profile/年龄层中两个分组都达到门槛，才提出探索性单变量比较草稿建议；展示比较样本和 5 秒完播中位数，不宣称显著性或因果关系。没有官方数据时只有人工统计；未达门槛没有作品表现建议。Challenger 与实验在后续独立 PR。

读取上限为 10,000 个去重作品和 200,000 条周覆盖证据；超限明示不完整，所有分组降为不足。报告生成不扫描媒体、不运行 FFprobe。旧 insights 排除目标作品自身；小样本、跨类型或年龄回退标不足并禁止建立正式作品实验。旧周报对缺乏同类对照的作品保留 `insufficient`，不能因回退全体而变为普通/好/差。

### 迁移、验证和回退

第 16 项增量只新增报告表与索引，升级前备份、事务内迁移，旧事实不变。测试覆盖旧库保留、失败回滚、并发幂等及备份恢复；另覆盖报告重复生成、冻结后源数据变化、无账号/无官方数据、跨账号、最新未匹配、改标题去重、同批碰撞、旧时长优先级和浏览器读写边界。

功能回退撤下报告生成入口，保留报告及源事实。不能通过删迁移账本来恢复旧 readiness；旧二进制须先在副本验证，整库恢复要保存当前新增事实并核对外部发布记录。

## v2.5.5 PR1：初始候选观察与明确审片

本阶段复用 `ai_analysis_runs.analysis_payload_json` 和 `clip_feedback`，不增加候选事实库。后续官方作品特征、冻结报告、Challenger、实验与正式启用仍须独立 PR；本文不代表完整 v2.5.5 已发布。

### 初始观察

`review_observation_service` 定义 `review-observations-v1`。康熙与共享内容 Analyzer 评分后保留轻量观察，继续按原规则去重、过滤 A/B、选择默认 A 级；未入池 C 级、去重或数量限制排除项只保存在 Run 的 `analysis_meta.review_observations`，不插入 `clip_candidates`。

每条记录包含 Run 内来源键、初始推荐、是否入池、时间边界、标题摘要、等级与评分维度、topic、可获得的 hook、排除原因及内容哈希。没有转写全文或帧图片。池内键为 `clip:<clip_id>`，诊断键为 `source:<source_id>`，必须连同 Run ID 使用；重新分析复用数据库候选编号不能改变旧反馈归因。

记录只增加结果元数据，不改变康熙 Prompt、评分、片长、去重、默认选择、必需阶段 checkpoint 输入或原子提交边界。通用模型默认产生的 `selected_by_default=True` 不足以证明原始推荐，统计记为未知；无等级的历史默认 `quality_score=0` 同样保持未知。

历史 Run 只读解释已有 JSON，不回填版本或重算；旧访谈/知识 schema 2 已有的 `analysis_meta.observations` 继续提供 C 级与可准确区分的未入池观察，不因新字段缺失而丢掉旧证据。新观察哈希异常、重复来源键、旧 JSON 无法读取会显示证据不足，不拿当前候选补猜。Run 正文继续使用原应用层快照语义，并未宣称数据库增加了禁止更新正文的触发器。

### 明确评价与生产选择

片段审核页增加可展开的“评价 AI 初始候选”区：选择具体分析批次，查看原始时间与内容后明确接受或拒绝，拒绝须选择原因；诊断片段须另行展开。该动作只记录对原始建议的评价，用户仍在原审片界面保存启用、编辑边界与生成切片。

`POST /api/tasks/{task_id}/ai-analysis-runs/{run_id}/review-observations` 在 `BEGIN IMMEDIATE` 内核对任务、Run、来源键和观察哈希，然后写 `clip_feedback.decision_source=observation_review`。同一原始评价的重复或并发提交返回同一记录；重新改变决定形成新记录。C 级评价不创建生产候选、Workflow Job、成片或发布任务。

新来源从原普通选择去重、候选淘汰原因、近期康熙反馈上下文和旧作品反馈查询中排除，避免诊断进入旧生产策略或旧表单字段。新人工统计显式读取它。旧 `explicit_feedback` 接口保留原行为，但读取当前候选、归因与修改现在在同一写事务，避免重新分析复用 ID 时跨 Run 修改。

### 统计口径与可信边界

Content Review 的人工审片区不需要官方账号，统计跨任务/Profile，不受抖音账号选择影响。

- 时间窗口是“最近 30/90/180 天生成的 AI 分析批次”，使用截止时间前的最后明确评价。跨批次重复分析算不同推荐尝试，不冒充不同原片。
- 新评价按 Run + 来源键 + 哈希归因。旧明确反馈仅在数据库候选编号能唯一对应 Run 内片段，且初始边界、标题和摘要完全一致时计入。普通 `review_toggle`、启用状态、自动 `reviewed=1` 不算明确评价。历史无 Run、找不到来源或内容已经修改的反馈单独显示未知/歧义。
- AI 推荐接受率 = 已审推荐中接受数 / 已审推荐数；同时展示已审推荐数、总推荐数和覆盖率。等级与分数组展示所有已审候选的接受率，避免 C 级因未默认推荐而永远没有人工结果。没有分母显示未知，不显示 0% 或 100%。
- 各组显示接受/拒绝/未审、任务/Run 数、拒绝原因、未知版本及可信等级。至少 20 个可归因且文字分析完整的决定、3 个已核验原片文件，且同一明确 Profile，才能标“探索性”；展示分母中若混入不完整分析或未知原片身份，整体仍标不足，不用更干净的子样本替整体背书。推荐接受率另外检查已审推荐自己的 20/3 门槛。跨 Profile 等级/分组不被当作可信对照。
- 当前只复用**同一 Run**视觉采样已生成的完整原视频 SHA-256。没有这份证据的文字任务保持原片身份未知；不会用音频哈希、首尾弱指纹或任务数量代替。完整哈希只能识别字节相同的副本，不证明重新编码的不同文件属于不同节目。后续素材身份能力须补独立证据，不能为凑门槛开启视觉模型。
- 单页最多计算 2,000 次分析、200,000 个反馈事件，超限显式标“部分统计”并禁止达到可信门槛。页面查询不运行 FFprobe、扫描长视频或调用 AI。

### 数据库与回退

第 15 项迁移 `20260915_01_human_review` 只在 `clip_feedback` 增加可空 `analysis_candidate_key`、`observation_sha256` 和 Run/候选/时间索引，旧行原样保留。沿用既有迁移账本、备份与事务，不修改已应用迁移 checksum。

功能回退可撤下新评价/统计入口，保留反馈和 Run 元数据，旧生产选择入口继续可用。旧二进制可能因未知迁移拒绝 readiness；不得删账本或覆盖生产库伪装回滚。完整回退先在副本验证并保存当前数据，数据库恢复不撤销外部发布事实。

### 本阶段验收

单元/集成验证默认选择歧义、Run ID 复用、最后决定和截止时间、明确反馈重复提交、C 级只评价、原片哈希去重、小样本和损坏快照；迁移验证历史字段不变、失败回滚、并发幂等及备份恢复。浏览器验证无账号页面、桌面/手机布局、拒绝原因与诊断展开，不调用真实模型或发布。完整结果以 PROJECT_STATUS 与忽略的本机验收目录为准。

## 当前增量：批次自动生产

素材池明确勾选 `auto_production` 后，Task 冻结 auto_mode，`material_import` 成功时复用 `mark_job_completed_with_followup` 在同一 lease 事务完成父 Job 与创建/复用 auto_pipeline。复制证据已提交而 followup 失败时保留原副本，重试重新验证完整哈希再完成该事务；不会创建第二个有效后续 Job。

批次 Pipeline 仅允许 PREPARING_SOURCE、TRANSCRIBING、AI_ANALYZING、CLIP_SELECTING、VIDEO_CUTTING。原 handler/checkpoint 继续复用，完成后核对成片执行证据并设置 pending_review，完成 Workflow Job 释放槽位。即使恢复请求显式指定 metadata/schedule 步骤也拒绝。选择数量采用冻结 final_clip_target；未启用自动生产的旧批次不被接管。

AI 不确定/部分失败遵循原失败和人工重试规则；部分切片失败保留结果并显示失败，不能当作全部完成或批准发布。此增量无新迁移，不开放全自动排期。统一 Inbox 与首页已接入后续工作台 PR。

v2.5.5 的版本、运行与数据兼容验收已完成。v2.6 沿用 FastAPI、SQLite、本地文件和 Windows Worker，不增加队列基础设施。每个相邻 PR 合并后再开新短期分支，整版验收后更新原正式服务。

## PR 顺序

1. **素材目录与登记**：不可变预览、本机路径边界、文件版本、明确确认、幂等登记和素材池页面。先独立验证文件读取，不建立虚假父任务，不复制视频。
2. **批次与任务导入**：冻结 Profile/Prompt/Provider/数量/字幕/生产选项；在一个事务内创建真实任务占位、批次项及 task-bound material_import Job。逐个复制到现有 E 盘托管目录，校验全量内容哈希与媒体，保留外部原片。
3. **受限生产队列与恢复**：claim_job/claim_next_job 同事务限制全局重型并发，复用 token fencing/checkpoint；失败不挡后项，人工等待释放执行槽。AI 不确定计费仍需人工处理，不能无限重发。
4. **预切后人工凭据与 Inbox**：批量任务专属凭据绑定 Run、实际选择/边界、切片版本，所有内容准备/同步/排期入口都验证；旧任务保持兼容。统一投影待审片、字幕、发布复核与异常，不新造状态机。
5. **工作台与整版验收**：聚合生产数据、十视频导入/并发/重启/失败演练、旧流程回归、Windows 实机门禁及原服务升级。真实选片质量继续日常补验。

原计划的“素材池/批量任务”拆成两份，以分开验证目录读取和后台媒体写入。后续数量可按真实风险调整，不合并跨版本开发。

## 素材登记契约（PR1）

用户通过原本机管理入口显式输入目录；扫描只读目录元数据，非递归，最多 1000 个目录项和 200 个视频。拒绝网络/设备/相对/跳转路径，拒绝目录及祖先重解析点、符号链接；映射网络盘同样拒绝。不改变任何全局媒体 allowlist，也不提供从登记路径直接下载任意文件的路由。

预览保存原目录身份、每个文件的完整路径、大小、mtime/ctime、device/inode、排除项与清单哈希，有效期 30 分钟。视频扩展名可登记不代表媒体解码成功。用户选中的 source_key 必须来自该预览；确认时重新核对目录与文件身份，有一个变化则整次事务回滚。相同源路径及元数据版本的重复/并发登记复用 source_materials；相同请求 UUID 只返回原回执，不能携带另一份请求正文。

素材 `identity_sha256` 为元数据 JSON 摘要，**不是视频完整内容哈希**。现阶段不读取几十 GB 视频计算预览哈希、不创建 Task/Job、不调用 AI。原文件之后变化不会覆盖旧登记版本；重新扫描建立新版本。完整内容 SHA-256、来源真实性和解码预检必须由下一阶段导入 Job 再验证，不能仅凭登记记录安全激活任务。

当前预览过期只阻止登记，清单仍作为本机元数据保留；未确认预览的保留/清理将在队列生命周期收尾中处理。浏览器同页丢失响应时复用请求 UUID；刷新后重新扫描可能新增一条登记回执，但唯一 source_key 保证不重复建立素材。下一阶段批次需额外实现跨刷新/重启的完整请求幂等。复制前还需校验实际打开的句柄；目前元数据扫描与 stat 之间没有文件锁，不能作为无竞态的字节复制证明。

## 导入和审核后续必须遵守

- 复用任务插入与 create_or_get_active_job_with_connection，不以普通 active Job 去重替代批次幂等；现有 helper 只比较 task/type，不比较源文件。
- 复制使用临时产物、输入版本/完整哈希和当前租约验证；最终路径和数据库关联在受控提交点激活。迟到的旧 Worker 不能覆盖新租约产物。
- Batch 配置和实际 Run 策略保留证据，不自动跟随正式 Prompt 更新。一个素材按不同策略再次生产必须明确创建新任务。
- 自动任务允许预切；人工确认前不得进入内容准备与排期。reviewed/enabled 不能代替独立人工凭据；切片期间候选被修改不能误记实际成片边界。
- Inbox 按任务、Job、cut、字幕 revision、publish job 及审核凭据查询；不复制另一份待办状态，不加载全量转写/逐行 FFprobe。

## PR2 已实现的导入契约（未部署）

- 批次配置/API 支持五 Profile、Prompt、Provider、候选/最终数量、时长、长直播策略、视觉与字幕策略。自动生产参数当前只接受 false，不能静默忽略 true；字幕策略作为后续交付决定保存，本阶段不自动产字幕。
- 单事务创建无源 Task、不可变批次项及 material_import Job；目录由 Job 后建。同请求 UUID 原样返回，正文变化拒绝；另一请求默认遇到已生产素材整批拒绝并显示原任务，显式再次生产才新建。
- 每项冻结原 generation_snapshot_v1，之后 AI Job 复用该快照，批次任务不能修改策略或切换 Provider。正式 Prompt 更新不重写已排队配置。
- 实际打开原片后校验句柄身份，与路径版本分别核对；完整原片哈希双读+副本 SHA-256、媒体双轨解码与剩余空间通过后才激活。Python/Windows 的路径与句柄 ctime 语义差异通过分别前后比较处理，不弱化 dev/inode/size/mtime 和内容检查。
- 复制临时和最终文件名都绑定租约 token。当前租约事务提交导入证据和 Task 源，原 Job 完成失败可基于成功副本恢复；旧租约提交被拒绝，未引用的旧 claim 残件仅在托管 source 目录清理。外部原片不删除。
- 浏览器首次请求前保存正文及 UUID；刷新不自动发送，仅提供原请求重试。任务入库与外部媒体复制不在一个事务，部分复制失败明确显示原 Job 错误，可重试，不将半成品当作可处理源。
- 全局并发限制在下一 PR；当前沿用已有 Runner 行为。导入结束后为 pending_processing，尚不串联自动转写/生产。统一审片凭据/Inbox 在后续 PR 实现，不以本 PR 代替整版 v2.6 验收。

PR2 验证记录：17 项新增功能/迁移/浏览器定向通过；完整离线基线 1283 项通过，收集后修正通过最终 15 项批次/Chrome 增量验证，另有 cuts-async 409 门禁单项。静态检查全过。路径边界测试包括预先存在的重解析点模拟、源句柄身份差异与正常 Windows 真实文件复制；未声称覆盖具有本机写权限的其他进程在检查后主动替换托管目录的所有竞态。当前文件系统操作沿用本机单用户信任边界，路径检查并非目录句柄沙箱。

## PR3 容量与恢复（未部署）

数据库事务限制所有 Workflow Job 默认一个有效 running 租约，direct claim 也不能绕过。next_attempt_at 保持有效；同秒按原插入顺序，批次按文件名创建。完成/失败/人工等待释放槽位，仍在执行的取消请求不能提前释放。

执行进程另外持有 SQLite 同目录的 OS 文件锁，阻止“Web 已死、旧子进程尚存”的物理并发。等待最多 120 秒，持续显示等待、验证当前租约和取消；无锁不会调用实际处理函数，不按 PID 杀进程或删除锁文件。无论正常退出还是进程树死亡，OS 负责释放互斥。Publisher 独立执行机制不变，没有引入外部队列。旧 AI 不确定结果仍按原 checkpoint 规则人工确认。

本 PR 无 DDL，migration regression 继续验证已有 21 项；真实短视频复制回归、实际双进程争锁/进程树结束、十路混合领取、FIFO、取消、重启与 timeout 定向通过。旧断言中允许 live Job 同时领取其他 Job 的部分已改为新串行验收。

容量范围是 Workflow Job 队列。旧同步 audio/transcript/cuts API 和独立 Publisher 尚不属于此锁；批次自动生产后续只走受控 Job 入口。1289 项完整离线回归、Ruff、编译及 12 JS 检查通过，正式部署仍等待整个 v2.6 验收。

## PR4a 成片执行证据（人工凭据前置）

代码审查发现原 output_clip 的边界来自提交时读取候选，而不是执行时的 CutPlan，因此先独立修复这一可重现风险，再实现统一人审。新 cut_run_evidence 保存切前选集/Run 哈希和结果，准备及提交两处核对；成片实际时间来自 FFmpeg 已执行的 start/duration。变化时整批拒绝激活，旧结果保留。此 PR 不开放自动生产、不创建人工确认，不替代后续字幕/发布服务门槛。

边界证据表示实际执行的 FFmpeg -ss/-t 计划，不是从成片解码反推的首尾帧；fast copy 仍可能受关键帧影响，策略也被记录。Run 快照同时冻结实际 Provider、模型、Prompt/Profile 版本和哈希、请求数量及分析载荷哈希。当前下游统计兼容 cut_plan_v1 标签；新人工凭据必须读取并校验 cut_run_evidence 与 output_clip 一致性，不能只看标签。


## v2.6 生产工作台与统一待办

## 本地清单

在未跟踪的 `data/acceptance/content-profile-v2.4/` 保存 manifest.json、原始响应、回放结果与人工记录；媒体、私人转写、真实 Prompt 正文、完整数据库不提交 Git。
至少三集不同康熙节目，覆盖稳定高质量、跨窗互动、候选不足；新访谈/知识各另选两条合适素材。

| 字段 | 必须保存 |
| --- | --- |
| sample_id/content_type | 脱敏编号、内容类型 |
| source | 本地路径、大小、SHA-256、FFprobe 时长，原片不改 |
| transcript | 路径、字节哈希、转写器/语言/配置与时间范围 |
| strategy | 基线提交、Profile/规则版本、参数、Prompt 版本与正文哈希 |
| provider | 实际 Provider/模型/推理配置指纹，不包含 Token/Cookie |
| baseline_run | 历史 Run/Job、阶段请求/响应哈希、coverage、失败/不确定单元 |
| replay | 新提交/输入指纹/响应来源、窗口与候选边界/排序/分数/等级/默认选择 |
| blind_review | 匿名 A/B 映射独立保存、审阅人/时间、逐候选结论原因、总门禁 |

缺失来源明确为空附原因，不补猜。

## 两层验收

1. 确定性回放：相同转写、Prompt、Provider 配置、冻结响应输入旧/新路径，比较窗口、边界、排序、分数、等级、默认选择与请求指纹。抽配置本身应一致；成功单元复用，不确定不能记成功。原响应缺失时明确无法证明该样本回放等价，另补完整样本。
2. 真实质量对比：独立记录真实调用和新 Run，随机 A/B 展示原片上下文与候选，检查铺垫、核心价值/笑点、反应、收尾、断章和重复。新增断章、丢笑点闭环或明显回退即失败，修正复验；数量与 AI 自评分不代替人工结论。

人工通过前不宣告 v2.4 完成、不进入 v2.5。访谈/知识按自身价值与完整性检查，不套用 humor 门槛。

## 可提交证据

仅提交脱敏样本 ID、输入/结果哈希、代码提交、模拟/真实标记、差异与人工结论摘要；完整材料留本机。版本记录具体命令、通过/失败/跳过、CI、实际运行版本和未满足门禁，不用旧测试数冒充当前结果。

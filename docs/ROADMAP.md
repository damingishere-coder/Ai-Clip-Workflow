# 项目路线图

## 版本策略

- **P0**：紧急修复和安全补丁

- **P2**：工程化与架构演进准备
- **P3**：分布式与多机协作
- **P4+**：多用户与平台化

当前版本：**v1.2.0**（P2-1 阶段）

## 计划中

### P2-3 — 本地 Job Worker

**目标**：将耗时任务异步化，不阻塞 HTTP 请求。

| 任务 | 说明 |
| --- | --- |
| 引入 `asyncio` 后台任务 | 转写、AI 分析、切割在后台执行 |
| 任务进度实时推送 | SSE 或轮询，前端可看到实时进度 |
| 任务队列管理 | 支持任务排队、取消、重试 |
| 并发控制 | 限制同时进行的 FFmpeg/转写/AI 任务数 |

### P2-4 — 本地安全增强

**目标**：加固单用户本地使用的安全边界。

| 任务 | 说明 |
| --- | --- |
| 操作确认对话框 | 删除、清空回收站等敏感操作需二次确认 |
| 操作日志 | 记录关键操作到 `audit_log` 表（本地 SQLite） |
| Token 管理 | `LOCAL_ADMIN_TOKEN` 过期/刷新机制 |
| 文件校验 | 上传文件 MIME 类型和大小校验 |

### P2-5 — 存储灵活性

**目标**：让存储根目录可以灵活配置，支持 NAS。

| 任务 | 说明 |
| --- | --- |
| NAS 路径验证 | 启动时检查 `STORAGE_ROOT` 是否可达 |
| 网络路径支持 | UNC 路径（`\\NAS\share`）读写测试 |
| 空间检查 | 新建任务前检查磁盘剩余空间 |

### P3-1 — 数据库升级

**目标**：从 SQLite 迁移到 PostgreSQL。

| 任务 | 说明 |
| --- | --- |
| PostgreSQL  schema 设计 | 对应现有 10 张表，利用 JSONB、枚举类型 |
| 数据迁移脚本 | SQLite → PostgreSQL 一键迁移 |

| 查询优化 | 利用 PostgreSQL 索引、全文搜索 |

### P3-2 — 消息队列与 Worker 分离

**目标**：API 和 Worker 解耦，支持横向扩展。

| 任务 | 说明 |
| --- | --- |
| Redis 引入 | 缓存 + 消息队列 Broker |
| RQ / Celery Worker | 独立 Worker 进程处理耗时任务 |
| API 只做调度 | Router 层只负责创建任务、查询状态，不执行处理 |
| Worker 监控 | Worker 心跳、任务超时、死信队列 |

## 暂不计划

以下事项**目前不在路线图中**，等有明确需求后再评估是否加入：

| 暂不计划 | 原因 |
| --- | --- |
| SaaS 多租户平台 | 个人工具定位，不需要计费、租户管理、SLA |
| 真实全自动一键发布 | 平台风控/验证码/登录失效，技术上不可靠 |
| 强制云部署 | Windows 本地是核心场景，不强制上云 |
| 移动端 App | 工作流依赖 FFmpeg 大文件处理 |
| 实时直播流接入 | 需要流媒体技术栈（RTMP/HLS/WebRTC） |
| 多人实时协作 | 冲突解决和锁机制复杂度高 |
| 第三方 API 直连发布 | 抖音/B站开放平台权限门槛高 |

## 版本号规则

- 主版本号（P 阶段）：架构大变更
- 次版本号：功能增量（如 v1.1 → v1.2）
- 修订号：Bug 修复和小改进

当前 `VERSION` 文件记录版本号，`app/main.py` 中 FastAPI `version` 参数同步。

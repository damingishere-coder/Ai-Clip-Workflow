## 推荐方案：完整转写一次提交

针对本次的 Codex 棚内综艺任务增加显式的 `codex_full_transcript_v1` 分析模式。正常成功路径只调用一次模型：

1. 复用现有本地逐句转写，整理完整时间戳原文，不重复附加分钟章节。
2. 一次提交整期原文、冻结的“综艺·播放目标 v1”Prompt、评分规则、候选数和目标成片数，以及冻结的审片反馈。
3. 模型在一次请求中完成全片比较、候选边界选择和评分，返回已有候选 JSON 契约所需的全部字段。
4. 本地严格验证结果，再沿用现有自动选片、视频切片和人工成片审核。

正常路径从 18 次 AI 调用降至 1 次。不默认增加第二次 AI 复核。具体耗时以同模型、同素材的真实运行结果为准，暂不承诺固定分钟数或提速比例。

本次保留 gpt-6.1-sol、现有认证、原字幕设置、视觉关闭及播放目标规则。硬范围仍为 45–150 秒，允许少选，不为凑五条补分。人工审片、内容准备和排期边界继续保留。

## 质量和失败处理

- 全文请求必须覆盖转写首、中、尾，并保存转写指纹、请求模式/版本、Prompt/Profile/模型/反馈身份。
- JSON 结构、评分类型与范围、必填证据、起止时间、关键时刻、时长及重复候选均须通过本地校验。
- 继续计算现有音频辅助证据，保持当前评分计算与推荐门槛；不编造画面、笑声或逐词时间精度。
- 单次返回仍须建立可校验的成功 checkpoint，保留原始响应与解析结果。全文模式和分段模式使用不同恢复命名空间，不混用缓存。
- 分析元数据明确显示“全文一次分析”。成功单元记为 1/1，不沿用旧 18/18 的标签，也不把“全文已提交”说成模型已核实每一句。
- 超时、结构无效、边界越界、取消或结果不确定时保留现有结果和错误证据，暂停该任务；不自动换 Provider，不自动重复不确定调用，不放行切片。
- 超长素材先检查适配范围，超过经验证的输入限制则明确阻塞。本次不改造长直播、远程或本地模型的分析模式。
